# Argotech-vision-interview

开发环境配置思路

拿到面试题后，我首先按照任务类型将开发环境划分为Windows视觉环境和Linux ROS2环境，避免不同依赖相互冲突。OpenCV、YOLO和数据标注任务在Windows 11中完成：使用 Miniforge创建独立的Python 3.11 Conda环境，安装OpenCV、PyTorch、CUDA、Ultralytics等视觉库，并为Labelme单独建立标注环境；随后分别通过库导入、GPU检测和实际程序运行验证环境。

ROS2主要面向Ubuntu，而完整虚拟机会占用较多磁盘空间和内存。综合电脑存储、运行效率以及与Windows文件系统协同的需求，我选择使用WSL2安装Ubuntu 22.04 和ROS2 Humble，以较低的额外资源开销获得接近原生Linux的开发环境，并通过Talker/Listener发布订阅测试验证通信功能。

01 OpenCV的图像处理与形状识别 

在完成本题的过程中，我首先学习了OpenCV的基础图像处理流程，包括使用VideoCapture读取视频、逐帧获取图像、将RGB彩色图像转换为灰度图、使用阈值分割生成二值图、利用二值掩膜提取前景，以及使用 hconcat拼接画面、imshow实时显示结果、VideoWriter保存视频和释放视频资源等内容。同时，我重点学习了固定阈值与动态阈值的区别，并了解了Otsu算法根据当前图像的灰度直方图自动计算阈值的基本原理。

由于电脑前置摄像头不方便作为稳定、可重复的测试输入，我使用Codex先帮我编写了一个测试视频生成程序，制作了一段包含圆形、三角形、正方形和长方形的素材视频以作为我本体的“指定视频”。在生成这一段视频时，我尽可能让视频中能出现更丰富的图像类型和不同的曝光度，因此视频中的图形有不同的颜色、大小、旋转角度和运动轨迹，背景也包含亮度与渐变变化。

第一版程序采用了较为直接的处理思路：首先读取视频的每一帧，然后将彩色图像转换为灰度图，再对每一帧单独使用Otsu算法进行动态二值化。调用 cv2.threshold() 时将初始阈值设置为 0，并加入cv2.THRESH_OTSU，由 OpenCV根据当前帧的灰度分布自动计算实际阈值，而不是在整个视频中始终使用同一个固定阈值。最后，程序将原始画面、二值化结果和二值掩膜作用后的前景结果横向拼接并实时显示，同时在中间画面显示当前帧计算得到的Otsu阈值。

在开发过程中遇到的主要问题是测试视频使用了渐变背景，而Otsu本质上仍然属于全局阈值算法：虽然每一帧的阈值都会动态变化，但同一帧内部只能使用一个全局阈值。当背景不同位置的亮度差异较大，或某些图形与背景的灰度接近时，部分背景可能被误判为前景，从而出现大块白色区域或局部“花屏”。这属于全局阈值算法在不均匀光照条件下的局限，并不代表动态阈值没有生效。

对于后续优化，我的思路是能否尝试自适应阈值，使不同局部区域能够使用不同阈值，来达到修正“花屏”的目的；也可以先进行光照校正或背景估计，再执行二值化。

02 数据集标注任务

本题需要区分成熟与不成熟番茄，因此将类别统一定义为ripe和unripe，并把每个可独立辨认的番茄作为一个实例。前30张先按照自己对实例分割的理解，使用多边形逐个描绘番茄轮廓；第31～90张在学习 Labelme 标注规范后，采用更加统一的Amodal实例标注——当番茄被叶片或其他果实遮挡时，只要可见部分不少于约40%且能够明确判断类别，就根据完整形状补全被遮挡区域的轮廓，多边形可以穿过遮挡物，但不同番茄不得合并；最后10张尝试目标检测标注，使用Amodal外接矩形框覆盖番茄的完整范围，包括合理推测出的遮挡部分。整个过程始终排除叶片、枝干和背景，并保持类别名称一致。最终完成100张图片、774个番茄实例，其中包含666个多边形实例和108个矩形框实例，类别分布为591个 ripe 和183个 unripe。

通过三个阶段的实践，对比了实例分割与目标检测的标注方式，也逐步形成了明确、统一且可复查的遮挡目标标注标准

03 YOLO11n 模型训练

题目为多目标检测问题：一张图片中可能同时存在多个数字，因此模型不仅要判断数字类别，还要给出每个数字的位置，不能只使用普通图像分类。我选择了轻量级 YOLO11n。该模型参数量较小、训练和推理速度快，同时具备较好的检测精度，适合作为本次任务的基础模型。

数据集由程序自动生成，共包含2000 张640×640图片，并按照1400/400/200划分为训练集、验证集和独立测试集，类别为数字0～9。每张图片随机放置1～6个数字，生成图片时综合改变字体、字号、位置、旋转角度、数字数量、前景颜色和背景类型，并随机加入亮度、对比度、模糊、噪声及少量遮挡。背景包含彩色、灰度、黑色、白色和纸张风格，数字也包含黑色、白色、灰色和彩色，以降低模型对单一字体或固定背景的依赖。数字生成时同步记录边界框，并转换成YOLO所需的归一化标签格式。

完成数据生成后，我先随机抽取50张图片，将标签框重新绘制到原图上，检查类别和边界框是否正确。随后进行3个epoch的冒烟训练，用于验证数据路径、标签格式、CUDA和训练流程；确认流程正常后，使用YOLO11n、640输入尺寸、batch size 8和固定随机种子42完成 100 个epoch的正式训练。训练过程中记录Precision、Recall、mAP50、mAP50-95，以及 Box、Classification 和DFL Loss，并根据验证集mAP50-95选择最佳模型。最后使用完全独立的200张测试图片评估best.pt，同时保存PR曲线、F1曲线、混淆矩阵和预测结果。模型在独立测试集上取得 Precision 0.999、Recall 0.994、mAP50 0.993 和 mAP50-95 0.944。这些结果证明模型在当前合成数据上表现良好.

后续仍需加入真实拍摄、反光、遮挡、低照度和复杂背景数据，进一步检验模型的泛化能力

04 ROS2 学习与实现思路

分析题目后，我将 ROS2 部分拆分为环境搭建、基础概念学习、节点创建和话题通信四个阶段。题目指定 Ubuntu 22.04 和 ROS2 Humble，但电脑主要使用 Windows 11；考虑到完整虚拟机需要额外占用较多磁盘和内存，同时本项目的 OpenCV、Labelme 和 YOLO 已在 Windows 环境中完成，因此最终采用 WSL2 安装 Ubuntu 22.04，在保留 Windows 开发环境的同时获得接近原生 Linux 的 ROS2 环境，并将 ROS2 与 Windows 下的 Python 视觉环境相互隔离。

学习过程中，我先安装并验证 ROS2 Humble，通过官方 Talker 和 Listener 示例理解发布订阅通信，再按照题目要求学习节点、话题、服务和动作的基本区别。其中，话题适合持续传输视觉检测结果，服务适合一次请求与响应，动作适合需要反馈和取消的耗时任务。随后创建 arcotech_ros2_ws 工作空间和 Python 功能包 agri_vision_demo，分别使用直接实例化 Node 和继承 Node 两种方式输出 hello, world，理解简单节点与类式节点的组织差异。最后使用 rclpy 和 std_msgs/msg/String 编写发布者与订阅者：发布者每隔1秒向 /vision/plant_status 发布“检测到作物”，订阅者接收消息并输出对应日志。项目通过 colcon build 构建，并使用 ros2 node list、ros2 topic info 和 ros2 topic hz 检查节点、消息类型、发布订阅数量及约1 Hz的通信频率，最终完成了从环境配置、基础原理学习到指定话题通信功能的完整实践。
